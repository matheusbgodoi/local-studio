# Browser session ownership — September 7, 2026

MEASURED / PROVEN — source trace: the embedded browser extension sent `sessionId`, including unique child IDs, but the HTTP handler discarded it. All verbs then used the process-global active page. Independent agent contexts therefore did not imply independent browser state. Fallback navigation and remembered verification challenges were also global.

DECIDED / APPLIED — scoped browser verbs validate their owner identifier and dispatch through request-local async context. Each owner receives separate pages, a Playwright manager and a SHA-256-named profile beneath the dedicated browser profile directory. Cookies and storage are isolated; the unscoped user browser remains supported. Concurrent initial requests for one owner share page creation. Fallback navigation and challenge memory are scoped too. Pi session disposal awaits browser release, and network-boundary resets close all managers rather than only the original global one.

TARGET / NOT APPLIED — this source change requires installed browser acceptance. No model or live installed application was invoked for this change. Ordinary conversation profiles are retained on disk so restart/login state can survive; browser processes and in-memory owner entries are released. New child-profile retention is governed by the later bounded-cleanup change below. Automatic archival of existing profile directories is not implemented. Ownership is an application session boundary, not an OS sandbox against a shell tool with filesystem access. Search-provider cooldowns remain shared provider-level controls. Frontend pane affinity is handled in the following change so the visible panel can address its conversation's scoped browser.

DECIDED / APPLIED — the Computer browser pane already receives the focused conversation's runtime ID. It now uses that same ID for live-state/frame polling, navigation, mouse/keyboard input and viewport changes. Switching conversation remounts the surface so previous frames and navigation state do not cross conversations. HTTP browser middleware validates query affinity; extension body affinity remains supported. The default unscoped user surface remains available. This does not introduce a new child-browser selector; a child must be the focused conversation to inspect its browser through this surface.

MEASURED / PROVEN — manual source-browser diagnostics against an ephemeral loopback server opened two owner contexts concurrently. Their content was `alpha` and `beta`, cookies remained `alpha` and `beta` on the same origin, and their profile directories differed. Closing the first left the second readable. Both contexts closed normally. These commands used separate temporary data/profile directories, no installed application, no model and no external website. Logs: `/tmp/local-studio-browser-ownership-manual-20260907.log`. No automated test code was added.

DECIDED / APPLIED — runtime startup previously wrote browser/relay identity and model defaults into shared `process.env` before asynchronous extension loading. Concurrent child startup could therefore capture the wrong owner's identity even with separate browser hosts. A scoped Effect semaphore now covers environment injection through resource initialization and extension binding, restoring every prior value on success or failure before releasing the lock. Model discovery occurs before this scope, and inference is outside it. The automation extension captures its session's model default during loading instead of reading whichever model last changed process environment during later tool execution. Tool access remains explicitly assigned per session; the network service itself remains a process-level boundary and is not converted into a separate network namespace per child.

MEASURED / PROVEN — a manual deterministic offline invocation overlapped three startup scopes, including an injected failure. Observed identity reads were `owner-a, owner-a, owner-b, owner-b, owner-failure`, and the previous process environment was restored. Runtime and extension TypeScript passed. This verifies the scoped primitive and source wiring; actual concurrent browser extension tool invocations through the installed product remain an acceptance requirement. The earlier source HTTP routing diagnostic also returned `first` and `second` for separate query-scoped owners, independently of these extension-loading checks.


## New child profile retention

DECIDED / APPLIED — new browser owners with the `subagent:` runtime prefix allocate a freshly owned temporary profile directory. After successful context closure, disposal removes only that exact directory created by this manager. Normal conversation and default owner profiles keep their persistent paths. Existing hashed child-profile directories are not migrated, opened or deleted by this change. Concurrent stop calls share cleanup; reopening waits for cleanup to settle. A close failure preserves the directory and emits a fixed diagnostic, and a launch failure without confirmed browser closure also preserves it. Verification-window relaunch must successfully close the previous context before reopening its profile.

MEASURED / PROVEN — a manual source-browser invocation in an isolated temporary data directory launched a child and a normal conversation manager. The child directory existed while running and was absent after successful stop. The normal conversation profile remained. A preexisting hashed child-profile directory containing an operator marker was preserved unchanged. Runtime TypeScript passed. Log: `/tmp/local-studio-child-profile-manual-20260907.log`. No installed application, model, external website or new automated test code was used.

TARGET / NOT YET PROVEN — installed final6 child-browser acceptance remains pending. A crash or forced process termination can leave its owned temporary directory behind; automatic scanning/deletion of abandoned directories is intentionally absent. Completed or interrupted child tasks do not promise resumable browser cookies: ordinary cleanup discards their temporary profile. Persistent child task/transcript recovery is a separate capability from browser profile persistence.

## Installed final6 failure and cached-factory correction

MEASURED / PROVEN — installed final6 browser isolation **failed**. Two child tasks completed with HTTP 200, but all three left-child evidence files contained the right child's key and URL; the right child was correct. Recorded browser calls interleaved across all three rounds (left navigate, right navigate, left read, right read), so this was actual overlap, not a sequential false pass. The private final6 evidence includes `tool-order.json` (24 calls) and `external-checks.json` (six output files) under `/tmp/local-studio-browser-child-workorders-20260907/installed-final6`. No raw key is recorded here. Earlier host/HTTP isolation checks did not qualify extension loading.

ROOT CAUSE / SOURCE — Pi's resource loader calls `loadExtensionsCached`. Its own extension-factory cache returns the previously loaded module before the jiti `moduleCache: false` option is consulted. Browser module-level owner constants therefore survived across same-directory parent/child sessions. The startup semaphore protected initialization timing but could not refresh a cached module constant.

DECIDED / APPLIED — the embedded browser initializer now captures an explicit typed configuration on every factory invocation and passes that immutable configuration through its request helpers. Owner ID, endpoint, authentication headers and timeout are captured per session, even when the SDK returns the same cached factory. The timeout now covers response-body consumption as well as headers.

MEASURED / PROVEN — a manual offline invocation used the actual SDK `loadExtensionsCached` twice with the same source path and working directory, distinct owner environments, and a temporary loopback receiver. After restoring the process environment, the two registered `browser_get_text` tools sent `subagent:cached-left` and `subagent:cached-right` respectively. Extension TypeScript passed. Log: `/tmp/local-studio-browser-cached-factory-manual-20260907.log`. This proves cached factory capture in source; a new installed concurrent browser-tool run is still required.

DECIDED / APPLIED — Sitegeist relay configuration now uses the same per-initializer typed capture, including relay owner, endpoint, token and timeout. Automation model defaults also capture inside each initializer, not at cached module scope. Manual calls through the actual SDK cached loader and a temporary loopback receiver preserved left/right relay owners and left/right automation model defaults after process-environment restoration. No real automation, relay service or model was invoked. Extension TypeScript passed; installed Sitegeist/automation acceptance is not claimed. Evidence: `/tmp/local-studio-other-cached-factories-manual-20260907.log`.
